1. Problem and approach

A docked drone patrols a fixed property and streams telemetry and video. The owner needs two things: immediate alerts ("person loitering at the main gate at midnight") and a searchable memory ("a blue Ford F150 entered twice today", "show all truck events"). I built a streaming pipeline that turns each frame into a caption, then into structured detections, then into tracked entities, and evaluates rule-based alerts on the result. Every frame is written to a queryable index, and a LangChain analyst agent (Groq gpt-oss-120b) sits on top for summaries, recommendations and follow-up questions.

2. Assumptions

  • Dataset. As the brief allows, video frames are simulated as text captions, and telemetry comes from a small physical model (GPS per zone, altitude by mode, battery drain per 90-minute sortie). I wrote a 24-hour scripted day (92 frames, 27 events + routine patrol frames) in which each event targets one requirement: midnight loitering, a fence climb, a blue F150 entering twice, a whitelisted staff car, an unattended package, the gate left open, a car circling with headlights off, warehouse tampering, an altitude breach and a critical battery. Using a scripted scenario rather than a public dataset gives a golden test with known ground truth. For scale, a seeded procedural generator produces any number of frames.
  • Property. One site with 9 named zones (gate, driveway, garage, front door, parking lot, loading dock, warehouse, backyard, perimeter fence). The warehouse and fence are restricted after hours. Night is 22:00–06:00 and business hours are 07:00–19:00. All of this is in YAML.
  • Identity. Vehicles are re-identified by plate. When no plate is visible, a colour+make+model signature is used, and it is linked to the plate once both are seen together. People are distinguished by clothing description only. No face recognition, by design (privacy).
  • Real images. To test the VLM on real pixels, a script downloads 8 openly licensed Wikimedia Commons photos (fence climb, night gate, pickup with plate, loading dock, packages, dog, parking lot, a person with a light at night). Each is replayed at a time and zone (a "manifest") so the time-dependent rules apply. These are ground-level photos, not drone footage. No public drone dataset was used because of time; that is the main external-validity gap.
  • Models. Gemini vision (free tier) captions real images; Groq openai/gpt-oss-120b (free tier, fast) runs the agent. Claude and local BLIP remain alternative backends behind the same interface. Keys live in a gitignored .env.

Agent design and context management

The challenge in "use context throughout the video" is that a day of footage does not fit in a prompt. ContextManager keeps three tiers, updated while frames stream: (1) a ring buffer of recent frames, (2) per-hour digests (label counts, zones, alerts), and (3) entity memory plus the full index, which is retrieved on demand. build_context(question) fills a character budget in priority order: alerts, then entities, hourly digests, frames retrieved by FTS for this question, and recent frames. Prompt size is therefore about 8k characters for both 92 and 50,000 frames, and exact details are always one tool call away. Every factual claim must cite HH:MM and a frame id.

Agent recommendations (generated from whole-day patterns)

  • After-hours hot-spots: perimeter fence (3), main gate (1), warehouse (1). Add motion-triggered floodlights and shift extra drone patrols to 22:00–03:00.
  • Perimeter breach detected: inspect the fence line and consider vibration sensors to cue the drone automatically.
  • Blue Ford F150 (plate MH14CD5678) entered 2 times: confirm it is a known vehicle and whitelist it, or flag it.
  • Drone hit critical battery during a night patrol: add a battery swap before 23:00 so coverage is not lost at the riskiest hour.

What went wrong first, and what I changed (full table: vlm_results.md):

  • Lazy negatives. The first prompt allowed "Clear view, no activity" for empty scenes, and the small Flash-Lite model used that shortcut for the night gate (a guard and two cars), the loading dock truck, the dog and the parking lot. Fix 1: the prompt requires every person, vehicle (even parked), animal and package to be listed. Fix 2, a self-check pass: any "no activity" caption triggers a narrow second question ("list every person, vehicle, animal, package… or NONE"), and the caption is regenerated if anything is found. In one run it re-checked 2 captions and corrected both. It costs one extra call, only on frames that claim to be empty.
  • Hint leakage. The zone hint led the model to invent a "warehouse roof". The prompt now says the hint names the location but must not add objects.
  • Parser bugs on real phrasing, each now a regression test: "plate WDS-947 is parked" read as WDS947IS; "Dodge Ram" was unknown; "one carrying a briefcase… climbing" chose carrying over climbing (actions now ranked by security relevance); "climbing over a gate" moved the person to the main gate (zone words now count as locations only after "at/in/near…").
  • Known limits. Captions vary between runs (WDS-947 vs WOS-947 on a small, blurry plate), so captions are cached by image hash for repeatable demos. The parked cars at 00:05 are on the street outside the property, but a single caption cannot tell "on site" from "beyond the fence", so the after-hours vehicle alert there is a false positive. Fixing it needs geofenced image regions.

5. What I would do with more time

  • Evaluate on real drone footage (e.g. VisDrone / UCF-Crime clips) with labelled ground truth, and measure caption to detection precision and recall instead of 8 hand-checked photos. Add structured-output captions: the VLM returns JSON detections directly, with the regex parser as the fast path and a cross-check.
  • Better VLM: compare the full Flash/Pro models against Flash-Lite (used here because the larger models were overloaded), add multi-frame context so the model sees motion rather than single stills, and mask regions outside the property so off-site cars do not raise alerts.
  • Embedding index: CLIP/SigLIP image vectors alongside FTS5 for "find frames that look like this" and cross-day vehicle re-ID; a hybrid BM25 + vector ranker.
  • Real detector and tracker (YOLOv8 + ByteTrack) for bounding boxes, true dwell time and trajectories (e.g. a car circling detected from its path, not from the caption).
  • Video summarisation at several levels: per-hour, per-incident and per-day summaries written by the LLM from the digests, plus incident clips cut from the index.
  • Learned baselines: "unusual for this site at this hour", based on historical counts per zone and hour, rather than fixed rules only.
  • Operations: alert delivery (push/webhook/VMS), guard acknowledgement and escalation, drone re-tasking (send the drone to the alert zone), and multi-site Postgres storage with a retention policy.

6. How AI tools were used

Claude Code (Claude Opus 5.5) was used as an agentic pair-programmer throughout (AI_TOOLS.md):

  • Environment: it detected that Python was missing, installed Python 3.12 with winget, built the venv and confirmed SQLite FTS5 support.
  • Design: it turned the brief into requirements with acceptance criteria and proposed the caption-then-parse pipeline and the SQLite + FTS5 index. I chose deterministic per-frame analytics, with the LLM only at the edges, for cost and testability.
  • AI-generated components: the object/action extraction logic, the 13 alert rules, the natural-language query parser, tiered context management and the LangChain agent. Before writing the agent it looked up the current Claude API (model ids, effort, refusal fallbacks) instead of relying on memory.
  • QA: it generated the test suite and benchmark. Running them, rather than reading code, caught real bugs: Rich markup swallowing log details, repetitive recommendations, and triple alerts for a single event (which led to alert merging).
  • Model integration: it added Groq and Gemini, listed the models each key could use, and picked from what was actually available (retired and overloaded models were found by calling the API, not assumed). It found the "lazy negative" captions by looking at the photos and comparing them with the captions, then designed the self-check pass.
  • Learning: FTS5 external-content tables, BM25 ranking, LangChain 1.x create_agent and context budgeting were new to me; the AI explained each one and I verified it by running code.
Summary: AI made a tested, documented end-to-end prototype possible in a single working session. The process that made it reliable was AI generation followed by execution and tests, then fixes.
